### 3.3 浏览器交互如何工作

| 功能 | 实际实现 |
| --- | --- |
| 全文搜索 | 页面加载 `search.json`，匹配文章标题、摘要、分类、标签与正文文本 |
| 分类筛选 | 在首页显示对应分类的卡片，同时将选择保存到 URL 参数 |

这些功能均由静态页面和浏览器 JavaScript 实现。网站运行期间没有接入 GPT 聊天、自动写作或生成图片服务；这里的「GPT 创建」指开发阶段的协作过程。

## 七、为什么完整 Markdown 放在独立分支

用户要求 `.md` 记录保存到 GitHub，但不在网站中展示。当前 GitHub Pages 发布的是 `main` 的仓库根目录，且存在 `.nojekyll`；把 Markdown 放在 `main/docs/` 中、仅不加导航链接，仍可能使该文件通过正式域名直接访问。这不能可靠满足「不进入网站发布内容」的要求。

本次采用独立记录分支保存本文件：

- 正式站点继续使用 `main` 的页面和资源。
- 完整 Markdown 放到独立记录分支的 `versions/V1.0.md`。
- 记录文件不加入 `content.json`，不产生博客文章页。
- 记录文件不进入 `search.json`、sitemap、导航、归档或分类。
- 记录文件不提交到 `main` 的网站根目录。

**该仓库是公开仓库，因此记录仍可在 GitHub 的记录分支查看。** 这里的「不展示」指不作为网站内容发布，不代表文档私密或受访问权限保护。

### 8.2 本地构建与预览

需要 Node.js 22 或更高版本，不需要安装第三方依赖。

```sh
npm run build
npm run dev
```

`npm run build` 调用 `scripts/publish-pages.mjs`：先校验正式域名与 `CNAME` 一致，再生成 `dist/`、检查产物，最后把生成文件复制到仓库根目录。

`npm run dev` 启动本地静态服务器，访问终端输出的地址查看效果。文章、图片或模板变化后应重新构建，再检查相关页面。

可以单独运行静态检查：

```sh
npm run check
```

浏览器检查脚本需要可用的 Chromium 系浏览器与本地预览服务器；默认路径针对当前 Windows 上的 Edge，也可以通过 `BROWSER_PATH` 指定浏览器路径。应在允许使用该验证方式的执行环境中运行，不能把脚本文件存在本身当成检查已经通过。

### 8.3 提交与发布后的核对

1. 提交修改后的源文件、图片以及构建生成的根目录文件。
2. 更新 `main`，避免强制覆盖已有历史。
3. 等待与本次提交对应的 GitHub Pages 任务完成。
4. 访问正式域名核对首页、文章、图片、版本与搜索。
5. 对于只存 GitHub 的完整记录，确认其不在 `main` 和网站发布文件中。
6. 把实际提交 SHA、运行 ID 与检查结果补入对应版本记录。
